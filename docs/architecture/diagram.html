AGENTFLOW / 系统架构

一次交付如何完成

从打上 flow 标签的 Issue 或控制台任务开始：控制端记下要做的事，工作端修改代码，GitHub 保存推送的提交和 PR。

01 / 交付边界

分支已推送，PR 就开好了吗？

  1. Flow 是持续跟踪的任务。一次开工称为 Attempt；其下可以有多个执行步骤（Job）。
  2. 首轮调用 flow.open_pr 时，控制端先核对分支并保存交付意图。收到匹配的执行结果后，才创建或认领 PR。
  3. 评审修订沿用这一轮的分支和 PR。控制端用 webhook 和主动查询核对已追踪 PR；归档后重新开工会产生新的 Attempt。
02 / 恢复边界

工作端断线，谁能接着跑？

  • 同一身份的工作端重连，核对任务凭据与原工作区；结果若已生成，可以重送，控制端按持久记录继续处理。
  • 能证明没有启动、没有待确认停止的任务，租约过期后才可重新排队。可能已执行但无法确认的任务过了恢复期限会被阻塞。
  • 断线、归档或结果入库本身都不能证明旧进程已经停止。回收旧执行并确认清理后，工作区才可安全复用。
