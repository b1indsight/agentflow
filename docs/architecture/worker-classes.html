    范围与读法

    44 个类精确对应 app/worker/**/*.py 的全部 ClassDef。两个 _OutputLimit 按模块区分；CodingAgent 提供执行生命周期及本地文件默认实现，Codex / Amp 显式继承。图共 58 节点、118 关系；12 个包外类（含 BubAgent）和 2 个函数锚点不计入 worker 类。

    箭头表达静态关系，不表达调用时间顺序或独占所有权。源码链接指向同一 checkout 的相对路径及核对行号；未展开全部共享模型。

    当前实现的职责与生命周期边界

    执行所有权与可替换连接

    WorkerExecution 直接持有 WorkerExecutor，管理本 Flow 的执行 Task、工具 Future 和停止任务，两者共用 ExecutionState。多个 Flow 共用 Runtime 的目录池及配置后端的 Agent；会话、工作目录、凭据与子进程仍属于各次调用。

    Gateway / Session / Dispatcher 属于共享通信包；连接回调管理握手、消息关联及观察者。断线不取消编码执行，推理任务则由该连接的回调拥有。

    四类操作共用后端实例

    CodingAgent 提供 start / resume / read_history / register_file / read_file。CodexAgent、AmpCodingAgent 显式继承它，backend 标识负责文件路由。Runtime 的 _agents 固定持有两个实例；编码与推理按配置选取，历史按 T- 前缀选 Amp，其余选 Codex，文件按登记后端解析。本地 Path 沿用历史后端，Amp 附件 URI 即使出现在 Codex 历史中也始终交给 Amp 登记。

    start / resume 共用 _execute：总超时、调用级最终字节预算、临时 schema 与严格 JSON 解码集中于基类；具体 _run 负责原生执行、空闲超时、有界管道和取消后 join。业务 schema 与 VCS 结果仍由调用方核验。

    AmpCodingAgent.run_process() 共用于编码、历史 export 和 AmpAttachment 下载。两个 _OutputLimit 分别属于 Codex 和 Amp；已无 _Init / _Result 类。

    实现文件：coding_agent.py、execution/codex.py、execution/amp_agent.py。

    持久证据、文件与推理

    ExecutionRecord 与 WorkspaceSlot 共享 WorkspaceBinding 身份。journal v5 保留 v4 只读转换；目录 manifest 只读写 v3，已删除 _LegacyManifest / _LegacySlot 和 v1 迁移。

    FileLinks 只保存通用 backend / source、去重与 lookup，不导入后端。Agent 校验并读取 LocalFile 或 AmpAttachment；后者仍有 URL / name / read 行为。

    WorkerInferenceCallbacks 直接调用共享 Agent.start，在既有 inference_path 执行，不新建每次调用的子目录，context=None。只读要求仅由提示词表达，仍需可信宿主授权与外部隔离。已删除独立 inference 模块、InferenceTask / InferenceOutput / Inference 及 capability。包外 BubAgent 也继承 CodingAgent，经本地端点复用同一回调，未加入 worker 的 _agents。自更新仍是独立 CLI 分支。

    数量沿革：旧图 33 类 → 合入 main 后 49 类 → Agent 职责收拢 48 类 → c0da88d 共享编码 / 历史实例仍为 48 类 → 删除 NativeAgentInference / _LegacyManifest / _LegacySlot 后 b8aa1fb 为 45 类 → 删除 TaskExecutor 后为 44 类。LocalFile、AmpAttachment 仅迁移；独立推理函数与包外接口已删除，执行回归 CodingAgent，无新增 worker 包装类。
