Runtime 按后端持有共享 Agent，编码执行与历史查询复用同一实例；每个 Flow 的执行状态独立，推理另用小输出预算实例。

    范围与读法

    48 个类精确对应 app/worker/**/*.py 的全部 ClassDef。两个 _OutputLimit 按模块区分；CodingAgent 是 worker 内接口。灰色边界类和函数锚点不计入。

    箭头表达静态关系，不表达调用时间顺序或独占所有权。源码链接指向同一 checkout 的相对路径及核对行号；未展开全部共享模型。

    当前实现的职责与生命周期边界

    执行所有权与可替换连接

    WorkerExecution 持有本 Flow 的执行 Task、工具 Future 和停止任务，与 WorkerExecutor 共用 ExecutionState。多个 Flow 共用 Runtime 的目录池及配置后端的 Agent；会话、工作目录、凭据与子进程仍属于各次调用。

    Gateway / Session / Dispatcher 属于共享通信包；连接回调管理握手、消息关联及观察者。断线不取消编码执行，推理任务则由该连接的回调拥有。

    编码与历史共享后端实例

    CodingAgent 提供 start / resume / read_history。Runtime 的 _agents 为 Codex、Amp 各持有一个实例，每个 Agent 拥有自己的 History；编码按配置取同一实例，历史按 T- 前缀选择 Amp，其余选择 Codex，不依赖活动 Flow。

    AmpCodingAgent.run_process() 共用于编码、历史 export 和 AmpAttachment 下载。两个 _OutputLimit 分别属于 Codex 和 Amp；已无 _Init / _Result 类。

    实现文件：coding_agent.py、execution/codex.py、execution/amp_agent.py。

    持久证据、文件与推理

    ExecutionRecord 与 WorkspaceSlot 共享 WorkspaceBinding 身份。journal v5 与 manifest v3 分别记录执行证据和目录库存；私有旧格式类只用于兼容读取。

    历史出站副本经 link_history() 登记文件，FileLinks 保存本地文件或 Amp 附件身份。NativeAgentInference 因输出预算更小保留独立 Agent，仅 start 独立会话；自更新仍是独立 CLI 分支。

    数量沿革：旧图 33 类 → 合入 main 后 49 类 → 删除 _Init / _Result、移入 CodingAgent 后 48 类。本次共享实例不改变类数量；编码与历史相关 Agent 从每 Flow 一份再加两份历史专用实例，变为固定两份。图中包外类和函数另计节点。
