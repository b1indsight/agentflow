# 前端样式风格指南

适用范围：`app/controler/web/` 及其子目录。

新增或调整 Web 控制台界面时，延续浅色、低饱和绿色、直角组件和连续工作区的开发者工作台风格，优先保障任务状态辨识和长时间阅读。相邻区域以细分割线和背景差组织层次。用户明确要求改变视觉方向时，仅调整本次要求的范围，其余部分继续遵循本指南。

## 样式来源与修改边界

- 修改前阅读目标组件及其在 [styles.css](../app/controler/web/styles.css) 中的规则；复用相邻同类组件的外观，不直接套用组件库默认皮肤。
- 共享基础色值统一定义在 [styles.css](../app/controler/web/styles.css) 的 `:root`；[theme.css](../app/controler/web/theme.css) 通过 `@theme inline` 引用这些变量，提供 Tailwind 颜色名称。业务样式与布局留在 `styles.css`，[components/ui/](../app/controler/web/components/ui/) 维护本地通用组件。
- 复用现有 `Button`、`Input`、`Tabs` 和业务样式；不为局部界面引入另一套 UI 组件库，也不借样式任务统一重写已有组件。
- 下文规定用途和视觉约定，具体色值、尺寸以对应源码为准。修改共享基础色时只改 `:root` 中的定义，不在 Tailwind 映射或使用处重写色值；映射按用途区分，例如 Tailwind `muted` 背景引用 `--bg`，`muted-foreground` 文字引用 `--muted`。
- 运行方式、滚动行为和渲染预算见 [README](../app/controler/web/README.md)。历史设计记录只用于追溯决定，不用旧方案覆盖当前实现与约定。

## 颜色与视觉层次

- 页面使用 `--bg` 浅灰底，内容面使用 `--paper` 白色；正文、辅助信息和分割线分别使用 `--ink`、`--muted`、`--line`。
- 链接、主要操作和选中项使用 `--green` 强调，浅绿背景使用 `--wash`；同一用途复用现有变量，不另造近似色。
- 状态沿用共享色表：待处理灰、进行中蓝、待审核黄、受阻红、已归档绿。复用 `phase-*` 与 `--status-*`，配合状态文字；看板卡片仅显示纯色点，完整状态通过悬停说明和可访问名称提供。
- 品牌绿与状态绿分开使用；已归档绿只表示阶段，成功或废弃由文字区分。错误文字和破坏性操作使用 `--destructive`，不直接使用亮红状态圆点色作为正文色。
- 用留白、浅底色和细分割线组织层次；默认不加入渐变、大面积高饱和底色、玻璃模糊或厚重投影。
- 保持现有浅色主题；本地组件中的 `dark:` 类不代表已有完整暗色主题，不在无关任务中补做主题切换。

## 字体与阅读密度

- 复用现有系统无衬线字体栈；代码、命令和技术标识使用 `--mono`，不额外引入远程字体。
- 正文和卡片标题使用 `--text-body`（16px），侧栏任务名使用 `--text-nav`（15px），常规控件和代码使用 `--text-control`（14px）。
- 辅助信息使用 `--text-meta`（13px），时间、计数等更次要信息使用 `--text-small`（12px）；影响操作判断的说明不能降成难以辨认的装饰文字。
- 详情主标题桌面使用 `--text-title`（28px），手机使用 24px。手机正文保持 16px，查询输入框也保持 16px。
- 正文行高沿用约 1.7–1.8，标题和强调文字沿用约 550–600 字重；通过层级、间距和折叠控制密度，不用缩小正文或整页缩放挤内容。

## 容器、控件与交互状态

- 矩形组件统一使用直角，不使用圆角矩形，包括按钮、输入框、标签、卡片、代码块、提示、菜单和弹窗。圆形头像、状态点、单选控件及品牌图标保留自身形状；不通过全局覆盖所有元素来清除圆角。
- 布局区域直接相邻，不用装饰性缝隙、重复外框或投影分开主工作区；用 1px 细线和轻微背景差区分区域。Dock 只画朝向内部的那一条边：左侧 Dock 画右边、右侧 Dock 画左边、底部 Dock 画上边，接缝不叠画双线。内容内边距继续为操作和阅读服务。
- 独立内容卡片和表单控件可保留细边框，普通内容面不使用浮起阴影；阴影留给浮层、弹窗和移动导航。悬停用背景或边框变化反馈，不抬升卡片。
- 看板卡片铺满列内容宽度，与列头、相邻卡片及列背景直接相接，不保留环绕空隙或四周描边；每张卡片仅用底部一条 1px 细线分割，内部不加分割线。保留卡片内部留白和悬停背景，键盘焦点线向内绘制，避免贴边裁切。
- 卡片首行仅在标题左侧显示一个 8px 纯色状态点，与 16px 标题的首行居中对齐；状态点形状相同，仅用阶段色区分，不使用状态图标或独立状态文字行。完整状态保留在悬停说明和可访问名称中；收尾中仍表示进行中，成功／废弃归档均沿用归档绿。次行以 12px 辅助字号左置仓库名、右置 PR 号，保持同行；无 PR 时沿用 Issue／Flow 编号回退。长标题换行，长仓库名省略并通过悬停保留全名，编号不挤出卡片。上下内边距桌面为 16px、手机为 18px，放宽内容与卡片边界的距离，不增加卡片外部缝隙。
- 新增间距先参考同类现有组件；常用 8、12、16、24px，但不把全部布局强制改造成固定网格。
- 主要操作使用绿色强调，次要操作使用描边或透明样式，破坏性操作使用现有 destructive 变体；根据操作语义选样式，不把所有按钮都做成主按钮。
- 标签页与阶段切换使用连续直角标签；未选中项保留辅助文字和面向内容的细分割线，选中项去掉该分割线，以背景差与内容面衔接，不再使用底部强调线或选中外框。标签过多时只让标签栏横向滚动。
- 侧栏选中任务使用整行浅绿底和深绿文字，不加独立外框。侧栏展开／收起按钮只保留图标，普通和悬停状态均保持透明、无边框、无阴影，保留点击区、辅助标签和键盘焦点反馈。
- 图标沿用 Lucide 细描边风格和所属组件的现有尺寸，已有品牌标记保留自身形状；会话头像保持圆形。
- 保留 hover、focus-visible、disabled、错误及提交中反馈。复用组件已有键盘交互与 ARIA 语义，纯图标按钮提供可访问名称。
- 动效采用局部短反馈，参考现有卡片的 150ms 悬停变化；不向正文阅读区添加会推动内容或扰动滚动位置的动效。

## 布局、窄屏与长内容

- 保持现有区域位置和信息架构；组件分割方式的调整不增加、重排或拆分布局区域。
- 沿用现有 760px 移动布局切换点及 1100px 紧凑布局调整；仅在有具体布局问题时新增断点。
- 桌面看板为五列独立滚动，列头不进入卡片滚动区；手机通过阶段选择显示当前列，不把五列压进窄屏。列高度由视口扣除顶栏、内边距、阶段选择和页脚后计算，卡片区再扣除列标题和内边距，不设固定最小高度。
- 看板列隐藏滚动条，但保留滚轮、触控、键盘滚动和原有分页、焦点恢复；仅作用于看板卡片滚动区，不用 `overflow: hidden` 禁止滚动，也不影响侧栏、详情及代码块的滚动条。
- 详情保持固定头部和独立正文滚动，阅读容器沿用现有宽度上限；手机侧栏使用带遮罩导航，阅读时详情头可收成一行，保留返回、PR/Issue 编号和短标题。
- 宽度不足时让控件换行、导航折叠、标题或路径按场景换行；避免整页横向溢出，不用页面级裁切掩盖撑宽问题。
- Markdown 正文代码块沿用浅底与等宽字体；正文代码块和工具活动代码允许换行，保留原始缩进、换行和完整文本。宽表格、专用 Review 代码上下文与 diff 保留各自局部滚动规则。
- 长正文和代码复用现有分段／窗口化组件；有界预览保留继续阅读入口，不用永久截断替代完整内容可达性，不为纯样式调整加载整篇历史或取消渲染预算。
- 工具活动和操作记录沿用紧凑摘要、按需展开；工具名和命令／参数同行，返回内容在下方用引用块展示，不显示 `call_id` 或“结果”标题。
- 普通消息不显示 `message` 标题，assistant 正文直接接续，不把所有消息再套一层卡片；编辑差异沿用浅绿新增、浅红删除及 `+`／`−` 标记。

## 验证

- 纯文档改动检查 Markdown 格式和相对链接，不要求运行界面或业务测试。
- 外观改动在实际页面检查受影响的默认态及选中、展开、错误等相关状态；至少覆盖桌面和手机宽度，可从现有回归的 1440px／390px 开始。捕获截图后实际查看，不能只依赖 CSS 和构建结果。
- 检查相邻区域没有装饰性缝隙或双重分割线，选中标签与内容之间没有残留强调线，矩形组件在普通、悬停和展开状态下均无圆角；圆形头像和状态点仍保持圆形。
- 交互改动检查键盘焦点、标签页切换及折叠后隐藏控件的焦点路径；长内容改动使用长标题、长路径、连续长代码和宽表格检查换行与局部滚动。
- 按 [README 的检查说明](../app/controler/web/README.md#检查) 运行改动范围对应的格式、类型、构建及回归检查；无法渲染或未执行的检查需在交付时说明，不把现有配色当成可访问性合规证明。
