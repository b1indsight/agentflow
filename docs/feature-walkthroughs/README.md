# 跟着一项任务使用 AgentFlow

选一个你有权限操作的测试仓库，准备好已连接的 worker。如果是第一次部署，先完成[快速开始](../../README.md#快速开始)。下面用「给导出功能加日期选项」作为例子；不需要了解内部类名，也可以判断每一步有没有成功。

1. [提出需求，拿到 PR 或待办问题](first-delivery.md)。从 Issue 或控制台开始，观察为什么同样显示等待审核，有时却没有 PR。
2. [在原 PR 上提问或要求修改](review.md)。看一条评审意见怎样得到答复，怎样留下一个新提交，以及什么时候线程仍应保持打开。
3. [补充输入、结束本轮、重新开工](continuation.md)。用任务编号、开工记录和 PR 判断自己是在继续原工作，还是开始新的一轮。
4. [查看执行时的会话](conversation.md)。从详情页读编码者看过的上下文，区分没有对话、原机器不可用与分页结束。

想定制任务开始时可用的项目指引？另见[为什么工作区里只出现了部分 skill](workspace-skills.md)，从控制台的来源设置一直查到本地工作区里的链接。

如果走到一半服务重启，或你准备更新执行机器，请看[断线后如何确认任务没有重跑](recovery.md)。它解释什么时候只需原 worker 重连，什么时候必须保留现场，以及如何停止接受新任务。

## 先认清你正在看的三处记录

**从任务详情开始，按问题选择下一处记录。**控制台把一项持续跟进的工作称为 Flow；每次正式开工称为 Attempt。记下详情里的仓库名和当前 Attempt，尤其是在同一个需求归档后重做时。详情回答的是「控制端把这件事跟进到哪里」。一次开工中还可能有几项分开执行的工作，例如首轮编码和按意见修订；查看 Job 列表可以分辨现在排队的是哪一步。

评审时转到 **GitHub PR**。PR 属于一个仓库，显示分支差异、提交和原始评审讨论。假设你在旧 PR 上看到「请改用 UTC」的评论，先确认任务详情里的交付链接指向这张 PR，再判断新提交有没有处理它。如果你想知道编码工具具体读到了什么，转到**会话**：工作端在原机器保存执行记录，控制台按来源读取或同步内容。任务卡片能打开，只能证明控制端找得到 Flow，本身不保证原会话此刻也能读取。

### 用一条补充要求走完三步

1. **选择已有任务。**打开「给导出功能加日期选项」的详情，确认仓库和当前交付。直接在已有任务里补充要求，可以保留同一次工作的上下文；从创建页再提交一遍正文，会得到不同含义的操作。
2. **写清可以观察的结果。**例如：「日期按 UTC 计算；输入 `2026-01-01T00:30:00+08:00`，导出日期应为 `2025-12-31`。」这个输入跨过 UTC 的午夜，比「注意时区」更容易检验。发送后先确认详情中出现这条原话。能读回消息说明控制端已经保存它；需要等后续执行才能检查代码是否采用了它。
3. **到对应位置验收。**如果系统还在等人选择日期格式，读详情中的问题并作答；如果本次交付已有 PR，打开改动和测试，检查跨日用例。读会话可以解释为什么编码工具选了某种处理方法，却不能替代对实际提交的检查。若任务已归档而你要开始另一轮实现，先读重新开工的走查，以免在旧 PR 上验收新需求。

## 怎样把一个界面现象对照到方法

举例说，你在详情里发送「日期请按 UTC 导出」。浏览器等的是 [`POST /api/flows/{flow_id}/agent-tasks`](../../app/controler/console/api.py#L341-L361)。这个入口把 Flow 编号、指令正文、请求编号和可选图片传给 [`ControlService.append_agent_task`](../../app/controler/workflow/service.py#L309-L338)。服务在锁住当前 Flow 后核对请求编号：同编号、同内容就直接返回；同编号、不同内容则报告冲突。接受新输入时先保存，再判断能否立即排队。这个方法并不向浏览器返回编码结果；HTTP 入口另外读取更新后的 `FlowDetail` 交回页面。

因此看到「消息已记录」后可以分两步核对。先在[会话走查](conversation.md)中确认这条输入没有被重复保存；再按[续办走查](continuation.md)认出哪个 Job 真正继承了这条要求。两次观察之间可能隔着其他工作，刷新页面既不会重发指令，也不能让尚未派发的进程提前看到它。其余走查也用这个顺序：先观察一次具体操作，再沿文中链接检查接收方承诺了哪些结果。

每篇都附有验证该行为的仓库测试。测试中的外部服务可以用替身，不需要向真实仓库发评论。准备在自己的环境做完整演练时，请使用[真实环境验收清单](../verification/m5-live-e2e.md)。读完想知道这些保证从何而来，可以换到[架构目录](../architecture/README.md)。
