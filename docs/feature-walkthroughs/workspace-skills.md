# 为什么工作区里只出现了部分 skill？

一个团队可能把写作规范、数据库约定和前端开发指引都放在同一个 skill 仓库。给导出功能改一个日期格式时，不一定用得上全部指引。AgentFlow 把这个选择分成两步：所有者先指定**从哪里取**，工作端在准备任务时再决定**哪些要放进这次工作区**。

## 先设置来源，再创建任务

以控制台所有者身份打开「设置 → Skill 仓库」，从已授权的仓库中选择一个来源，保存后重新打开设置，应当仍能看到该选择。模型设置不应随之改变。选择「不指定」可以取消配置。保存配置本身不会在浏览器或当前目录安装文件；见[选择与清除来源的测试](../../tests/test_console_api.py#L116)。

为了看出差别，可以在自己的测试来源中准备三项：一项常驻的写作规范（`always_on: true`），两项可选的数据库和前端指引。创建一项明显涉及改表的任务，观察这次新工作区的 `.agents/skills/`。工作端先链接可用的常驻项，再请独立会话根据任务和候选说明选择可选项。选择器看到候选名称、描述及声明的工具范围，无需把所有指引的正文放进提示里。

## 用工作区里的链接判断结果

如果选择器返回数据库指引，预期能看到写作规范和数据库指引的链接，看不到未选的前端指引。链接指向工作端取回的快照，不应作为本次业务改动出现在 Git 差异里。项目原本已有的同名项不会被覆盖。这里观察到的是“可供本次会话使用”；仅凭一个链接，无法证明模型已经阅读并采用该文件。

[工作区选择测试](../../tests/test_workspace_skills.py#L13)固定了选择结果，因此可以重复验证这三种情况。它还验证返回一个目录外的名字会被拒绝，而不会读任意路径。排查缺少的 skill 时，先分清是哪一步：控制台是否保存了正确来源，来源内是否有符合格式的 skill，以及该项是否常驻或被本次任务选中。[工作端实现](../../app/worker/execution/skills.py)分别处理快照、选择和链接。
