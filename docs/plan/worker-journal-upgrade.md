# Worker 直接前代 journal 升级兼容 — Feature record

**Stage:** Planning，待批准；本 PR 当前只包含计划，不包含实现或测试改动。
**PR:** 待创建；计划和后续实现使用同一个 PR。

## 1. Initial plan

### 动机与目标

用户要求正常更新 Worker 后不必手动删除、移走或编辑 journal，并明确本次只兼容直接前代：
**journal v4 / 协议 v14 → journal v4 / 协议 v15**。

当前 [WorkerSession.load](../../app/worker/state/session.py) 直接使用当前消息模型解析磁盘记录。
虽然前后两代 journal 都是 v4，但内嵌的 `terminal` 和 `stopped` 保留写入时的协议版本，
会被 [Message.protocol_version](../../app/contracts/protocol.py) 的 v15 限制拒绝。
[直接前代到当前版本的变更](https://github.com/b1indsight/agentflow/commit/19aada9f4928d0fa4dea58e41f36734406a7872c)
没有改变 journal 字段、这两类消息的业务字段或结果摘要算法，因此可以做有界的本地格式转换。

成功标准：保留原 Worker ID、root、任务身份、结果、停止回执和工作区归属，在同一位置用当前代码
重启即可读取合法前代记录、进行既有恢复和结果重放，无需额外迁移命令或人工清理。

### 范围与非目标

- 只兼容上述明确的版本组合，不使用“当前版本减一”来推断任意未来版本都可安全转换。
- 当前 v4 / v15 和没有 journal 的启动行为不变；没有内嵌消息的合法 v4 记录仍正常读取。
- 不兼容 v3 / 协议 v13，不迁移旧工作区目录，不推测缺失的工作区归属。
- 网络消息仍严格使用 v15；Server 必须支持当前协议，不增加新旧 Server/Worker 混用或协议协商。
- 不改 Server、数据库、安装器、`worker --update`、工作区池或执行器，不新增依赖。
- 不增加后台更新、自动重启或降级支持；既有停机、drain、任务收尾要求保持不变。
- 不修改当前运行中的 Worker、其真实 journal 或其他线程的未提交改动。

### 提议行为

1. `WorkerSession.load()` 继续负责读文件和校验 root 归属。
2. 对前代 v4 记录，仅在内存中把 `terminal`、`stopped` 的显式 `protocol_version=14`
   转换为 15；消息不存在或为 `null` 时不补造消息。
3. 转换后的数据必须通过当前严格模型、内容摘要和身份一致性校验，才能供恢复逻辑使用。
4. 读取不改写磁盘。后续正常 ACK、任务状态推进等写操作通过已有原子写入路径保存 v4 / v15。
   若没有发生写操作，下次仍可直接读取原文件，不要求操作者先执行一次迁移。
5. 重放时仍只由现有逻辑更新连接 epoch，不重新运行已完成的编码任务。

| 输入 | 提议结果 |
| --- | --- |
| 没有 journal，或没有内嵌消息的合法 v4 记录 | 保持现有行为 |
| v4，非空内嵌消息均为 v15 | 保持当前解析路径 |
| v4，非空内嵌消息均显式为 v14 | 内存转换、严格校验后恢复；正常保存时写为 v15 |
| v3、协议 v13、未来未知版本，或 v14/v15 混合记录 | 拒绝，不覆盖或丢弃原文件 |
| 损坏 JSON、未知字段或 root 不匹配 | 保持现有拒绝行为，保留原文件供诊断 |
| 前代转换记录的摘要或消息身份不匹配 | 拒绝转换，保留原文件供诊断 |

### 技术设计与受影响模块

实现预计涉及一个生产代码文件、一个测试文件和两份运行文档；本计划文件随同一 PR 维护。

- `app/worker/state/session.py`：增加私有解析函数
  `_parse_journal(payload: str) -> SessionState`，将磁盘格式兼容限定在本地读取边界。
  `WorkerSession.load()` 使用它，并保留既有 root 校验和 `SessionError` 错误边界。
- `tests/test_worker_session.py`：通过 `load`、`recovery`、`replay` 和 ACK 等公开行为覆盖兼容合同。
- `README.md`、`docs/deployment/worker-update.md`：说明准确支持范围、无需手工清理的更新方式、
  必须保持匹配的网络协议，以及不承诺降级或更早版本兼容。

不新增状态模型、持久字段或迁移注册表；复用 `SessionState`、`TerminalMessage`、
`ExecutionStopped`、`WorkspaceBinding` 和 `terminal_digest`。

私有解析函数的职责：

- 明确识别合法 v4 的当前格式或上述前代组合，不能对任意 JSON 递归替换所有版本号。
- 只调整两处已知内嵌消息的协议标记，其余数据交给当前严格模型验证；不删除未知字段来使其通过。
- 对转换记录检查终态消息的 job/token 与顶层一致；停止回执的 job/flow/token/nonce 与顶层一致。
- 对转换记录，若有终态，要求已保存的 `result_digest` 存在并与 `terminal_digest(terminal)` 一致；
  不通过重算并覆盖原摘要来掩盖不一致。
- 保留 state、acknowledged、执行 nonce、修订调用记录、归档任务、清理证据和 workspace 绑定。
  不改变 Server 既有的恢复、拒绝、停止确认或归档决定。
- 不在日志或错误中输出 token、完整 payload 或完整 journal。

摘要可保持不变的依据是 [terminal_digest](../../app/contracts/protocol.py) 只包含结果内容或错误，
不包含协议标记和连接 epoch；v14 → v15 没有改变终态结果结构。

### 方案比较与理由

- **采用：本地读取时转换。** 兼容只进入 journal 读取边界，不影响网络消息的信任边界。
  `load()` 也被只读检查工具调用，这些调用不保证持有 root 锁，因此读取不产生写盘副作用。
  正常运行的写操作继续复用 [write_private_record](../../app/worker/state/files.py) 和 runtime root 锁。
- **不采用：放宽共享 Message 模型同时接受 v14/v15。** 这会意外扩大网络协议支持范围。
- **不采用：启动时额外改写 journal。** 当前转换成本很低，既有保存路径足够，无需新增写盘步骤。
- **不采用：自动删除旧文件、重建 root 或丢弃终态。** 这些行为会丢失恢复证据。
- **不采用：复制整套旧协议模型或通用迁移框架。** 本次只有两个已确认兼容的版本标记需要转换。

### 风险、更新与回退

- 读取成功不等于任务一定继续执行：已失去原执行进程的任务仍走现有失败/恢复规则，不自动重跑。
- ACK 只确认任务结果，不代表 Flow 已结束；转换不能清空 journal 或解除工作区归属。
- 损坏、伪造或不属于当前 root 的记录继续拒绝；“无需清理”仅适用于本次明确支持的合法格式。
- 更新前仍须按部署说明停止共享安装的 Worker 并完成任务收尾，使用原 ID、root 和模型认证。
  源码更新及正式安装更新均在普通 Worker 启动读取时获得兼容，不改变各自安装方式。
- 正常保存为 v15 后，旧 v14 Worker 不保证能读取。回退前须确认状态边界，不在新任务开始后
  把旧 journal 复制回去；本 PR 不提供自动降级或执行中跨版本回滚。
- 未来协议变化必须重新核对结构和恢复语义，不能自动推广本次映射。

### 实施顺序

1. 计划获明确批准后，在隔离测试 root 中以独立构造的前代 JSON 重现当前读取失败。
2. 实现有界的本地解析兼容，保留当前格式、root 校验和现有原子写入行为。
3. 验证恢复、重放、停止回执、后续保存和拒绝路径，同步运行文档。
4. 完成相关回归、静态检查及简化/消融验证后，在同一 bookmark 和 PR 提交实现。

### 验证与消融策略

所有执行验证使用临时 root 和替身连接，不接管真实 Worker，不向真实 GitHub 仓库写入。

- 代表性升级：独立构造合法 v4 / v14 的终态与停止回执，读取后磁盘字节不变，恢复身份和摘要不变；
  重放消息通过当前严格网络解析器，后续正常 ACK 写入 v4 / v15，再次读取成功。
- 覆盖成功/失败结果和停止回执的不同内容，复用公开接口与参数化，避免给每个辅助函数单独建测试。
- 控制组：当前格式和无 journal 行为不变；未知/混合版本、错误 root、损坏文件，以及摘要或消息身份
  不符的前代记录均拒绝且不改文件；直接传入网络的 v14 消息继续被拒绝。
- 验证既有 WorkerClient 恢复/ACK/停止流程和工作区归属回归，不能仅证明 JSON 能解析。
- 运行相关 pytest、Ruff、Mypy 和 diff 空白检查；根据共享行为影响补跑 Worker 回归。
- 消融仅在临时副本中分别撤去版本转换、停止回执转换和新增摘要/身份检查，确认相应用例会暴露回归。
  这些临时变体不提交，也不作用于正在运行的源码目录。

当前仅核对了版本差异和代码边界；上述测试与消融均为待执行的验收要求，不宣称已验证实现。
方案咨询使用本地 Claude Code Opus 5.5，初始化与响应模型一致，工具和 MCP 列表均为空；
咨询结果只作为方案参考，当前限定范围按用户随后确认的“仅直接前代”收敛。
