# Amp 会话：从首轮采集，按缺口回填

**目标**：控制台可逐页读取 worker 发起的长 Amp 会话。新会话从首轮开始留存，旧会话和记录中断的会话可从 `amp threads export` 恢复。Amp 自己继续负责模型上下文和 `threads continue`；不承诺实时同步其他客户端新增的消息。

## 1. 初始方案

**验收示例（预期，尚未执行）**：同一 worker 启动一个首轮并续聊两轮，三轮累计超过 2 MiB。用现有 API 读取：

```python
page = get_conversation(flow_id, limit=1)
while page.has_more:
    page = get_conversation(flow_id, limit=1, cursor=page.next_cursor)
```

- 首轮输入、助手消息、工具调用与结果按顺序可见；两条相同正文不会被误去重。连续读取健康历史不调用 export，进程重启后可以继续分页。流中 final 与末次助手回答重复时不重复展示。
- 用超过旧上限的旧线程（如本次 2,295,061 字节的导出）模拟无本地文件，以及一次中途截断、缺失中段的本地历史。读取触发修复；修复后的完整分页与导出的公开条目序列相符，再读不重复导出。回填时并发开始续聊，不得覆盖新轮次。
- 损坏、超时、返回更短且未覆盖本地已知轮次的快照、超出恢复预算：保留旧文件与缺口，不能把不完整历史当作已修好。恢复后若已读位置失效，返回既有 `cursor_invalid`，从头加载。测试检查流、回填、失败路径均不持久化测试凭据或 thinking。

**接口与行为**：沿用 [Flow conversation API](../architecture/conversation-api.md) 的 `HistoryQuery` / `HistoryPage`、角色、分页和文件链接规则。由原 worker 在独立于代码工作区的私有目录，按已校验的 Amp session ID 维护 JSONL。记录 stdin 中的本轮任务与输出中的公开块；按真实 CLI 首轮/续聊样本核对消息、工具和结果格式，再映射角色。以白名单投影、脱敏并限制单条大小后才落盘，不保存原始 stdout、stderr、环境或 MCP 配置。保留执行结果校验、超时与停止语义。

进行中的轮次只读已提交的完整行。记录轮次起止、完整性和游标所属文件版本；识别旧会话缺前缀、缺文件、记录断裂、截断或异常退出后未完成的轮次。健康文件按字节偏移分页。仅在检测到缺口时为同一 session 合并修复请求；活跃写入期推迟回填。对尚未写入本地的外部轮次不声称能单凭本地文件检测到。

回填时完整消费导出并校验 session 和公开记录，使用独立于原 2 MiB stdout 缓冲的有界流式读取、超时与磁盘预算。生成脱敏候选历史；确认覆盖已知轮次且本地版本未变化，才原子替换。无法确认时保留原件并允许重试。不得仅按正文拼接两个来源；实现前用真实格式验证可用于确认覆盖的轮次边界或标识。不要求控制端改表，不回放模型，不修改线上 worker 或主动批量迁移旧 Flow。

**未采用**：仅提高历史导出的 2 MiB 常量仍需反复全量读取；仅记录最终答复会丢工具活动；直接持久化原始事件流会扩大凭据暴露范围。实现时同步更新 [来源说明与运维边界](../architecture/conversation-api.md)。

## 2. 变更时间线

### 001：回填保留控制台已发布的记录身份

Control 的活动记录以源条目 ID 为键。回填逐条按顺序验证已知公开块（角色、种类、工具标识及公开内容），在候选文件中沿用匹配记录的 ID；已导入块可按原生身份验证。游标随文件更换而失效，重读不会把已发布的记录作为新活动插入。见[分页与修复测试](../../tests/test_amp_driver.py)。

### 002：以工具调用 ID 和段内文本序号对齐（已实现）

保留 001 的已发布 ID 保证，取消逐条公开内容指纹。同一 session 内，`(tool_call, call_id)` 与 `(tool_result, call_id)` 是两个不同的锚点，即使多次调用同名工具也可区分。文本从最近的前置锚点起分配递增 offset；首个工具前和纯文本会话用 `start`。续聊接着已有记录分配，跳过 thinking，不计入 offset。

回填先匹配工具锚点，再在相邻已匹配锚点之间按顺序查找本地已知消息。offset 是已分配的身份，不能把 export 第 N 条直接当成本地第 N 条。用可用的角色和公开文本排除错配；只在对应关系唯一时沿用原 ID。已落盘的脱敏内容优先保留，不因重新导出而恢复已遮盖的数据。缺失的条目使用未占用的 ID，以 export 顺序展示，不重编号旧条目。无法确认覆盖、匹配有歧义或无法保证脱敏时，保留原件并报告未修复。控制端接口不变。

**验收示例**：`tool_call:X → tool_result:X → A → C` 中，A、C 已分别取得 offset 0、1。若 export 为 `tool_call:X → tool_result:X → A → B → C`，即使两次看到的工具结果渲染不同，也应保留 A、C 的 ID，仅为 B 分配新 ID，显示 A、B、C。若两个候选 C 完全相同且前后记录也无法区分，则不任选其一；导出缺少本地已知工具锚点时也不覆盖。

兼容旧会话：第一次读取时若只有 export，继续公开原生条目 ID，避免重复登记控制端已有活动。流式采集的文本首次回填用角色和脱敏文本匹配，以后可以直接按这次确认的原生 ID 匹配；两者都保留已分配的公开 ID。见[回填验收测试](../../tests/test_amp_driver.py)。
