# 输入框上拉扩展与图片附件

**阶段：** 已实现。

## 初始方案

[详情页输入框](../../app/controler/web/styles.css#L911-L924)目前使用浏览器原生纵向缩放，最大高度为视口的 18%。把调整手柄移到顶部：上拉增高，下拉缩小，底部发送区保持原位。根据可用视口限制高度，让小屏仍能操作发送按钮；手柄也支持键盘方向键。

[创建任务](../../app/controler/web/CreateFlow.tsx)和[追加输入](../../app/controler/web/AgentTaskInput.tsx)复用同一个文本输入组件。两处均支持通过文件选择器或拖放加入图片。每张图片在草稿中显示可移除的缩略图；发送失败保留草稿，成功后清空。本次只支持图片，不引入通用文件管理。

提交时把图片和本次输入关联，由服务端校验格式、大小和数量。worker 应当拿到可读取的图片内容，不能仅传浏览器预览地址或文件名。先核对执行器现有的图片输入能力，优先复用其支持的方式；不支持图片的执行路径应明确报错。纯文本提交沿用原契约。

先验证输入到 worker 的传输，再接入选择、拖放和预览。用浏览器测试检查上拉前后的上下边界、选择与拖放、移除及提交失败后重试；用 worker 集成测试比较提交和接收的图片内容，并覆盖纯文本输入。运行仓库的测试、构建及静态检查。

## 变更记录

- 图片字节与输入引用在同一事务写入。记录文本只含按内容生成的引用，组装任务时按 Flow 和引用还原图片。wire31 将图片送达 Worker；Codex 使用 `--image`，Amp 收到可用 `view_media` 打开的本地图片路径。文件随调用结束清理，不进入 checkout。
- 回归对照：未改动的 API 对含图片的追加请求返回 422；相同的数据库集成测试现在校验修订任务收到原图，并覆盖响应丢失后的重试。浏览器回归在 1440px 和 390px 宽度各向上拖动 96px，校验文本框增加 96px 且底边不动，再验证选择、拖入、移除及最终发送的字节。
