# 在 Flow 详情的区域间拖动文件页签（待批准）

## 操作示意

在会话中打开一个文件 A。详情区宽度为 960 px 时，初始布局有两栏。`●` 表示该栏当前选中的页签，`│` 是拖动时显示的插入线。

```text
拖前   [概览] [● 会话] [执行记录]      ║ [● A]
       会话历史                       ║ 文件 A 正文
拖动   [概览] [会话] [执行记录] │  ←──── 按住 A 的页签头
松开   [概览] [会话] [执行记录] [● A]
       文件 A 正文占满详情区
切回   [概览] [● 会话] [执行记录] [A]
       回到原来阅读的会话消息
```

## 验收示例

在当前 Flow 的任意两个可见页签栏之间移动已打开的文件。按住文件名或文件图标起拖；在目标栏的插入线处松开左键，文件移到该位置并成为目标栏的活动页签。关闭按钮仍然只负责关闭。拖到栏外松开或按 Escape 取消时，布局不变。

下面是拟用浏览器验证的操作和预期结果，尚未实现：

```text
详情宽 960：主栏 [概览, 会话*, 执行记录]，右栏 [A*]
拖放(A, 执行记录右缘) → 主栏 [概览, 会话, 执行记录, A*]，右栏消失
断言 A 只有一个页签；其正文占满详情区，移动前后的文件请求数相同
点击(会话) → 原会话消息回到视野；再点击(A) → 仍可读到文件 A

详情宽 1440：主栏 [概览, 会话*, 执行记录]，中栏 [B*]，右栏 [C, A*]
拖放(A, B 右缘) → 中栏 [B, A*]，右栏 [C*]；主栏仍显示原消息
拖放(A, 执行记录右缘) → 主栏显示 A；中栏显示 B，右栏的 C 保持可见
拖放(A, C 左缘) → 主栏回到会话；右栏 [A*, C]，中栏仍显示 B
```

星号代表活动页签。只在来源侧栏移空时收起该栏；来源栏仍有文件且移走了活动文件时，选右侧相邻文件，没有则选左侧。移动非活动文件不改变来源栏的选中项。主栏移走最后一个活动文件后可回到会话。从 960 px 缩至 959 px 时，每个未关闭文件在单栏仍只有一个入口；重新变宽不自行打开侧栏。验收时分别核对页签顺序、焦点和可见正文，并检查取消拖动不影响点击、Delete 关闭及键盘切换。

## 布局与接口

[现有详情组件](../../app/controler/web/App.tsx)根据侧栏当前选中的文件推算其他文件属于哪一栏；当主路由选中文件时，会隐藏所有侧栏。仅改变页签头的顺序无法保证正文移到同一栏，也会在三栏示例中误收起 C。

拟在详情组件中为每个区域保存有序的文件 ID，由同一布局决定页签头和正文。每个文件只属于一个区域，主栏沿用当前路由表示选中项，侧栏分别保存选中项。拖入主栏时使用现有文件页签 URL；两个侧栏间移动不改变主栏 URL。文件登记与读取仍以同一文件 ID 为准，移栏不等于关闭或重新打开。无需改动 Worker、HTTP 接口或文件缓存协议。

本次以**文件页签**为可拖对象，概览、会话、执行记录留在主栏开头。目标可以是任意现有区域，包括非最左侧的区域；不通过拖放创建新栏，也不跨 Flow 或刷新保存布局。沿用[现有宽度与文件读取约定](../../app/controler/web/README.md)和[页签样式与焦点规范](../STYLE_GUIDE.md)。实现时在[会话走查](../feature-walkthroughs/conversation.md)补上拖放示例，并扩展[现有浏览器用例](../../app/controler/web/e2e/console.spec.ts)。

## 方案取舍

单独增加“移到主栏”按钮无法指定插入位置，也无法把右栏的文件放进中栏。由目标页签栏接收拖放，可用同一操作覆盖这两种情况；代价是布局必须记录每个文件的位置，不能再由选中的文件反推归属。
