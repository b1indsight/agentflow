# Web 控制台

当前由 `flowtool serve` 在 `/console/` 提供，使用真实同源 `/api/`，**没有生产示例数据或 mock 回退**。
提供顶栏「新建 Flow」、详情底部「继续工作」、Flow「结束本轮」、已归档 Flow「恢复推进」及受阻 Flow 的安全重试。
页面、静态资源和 API 均要求 Cloudflare Access 的单 owner 身份；数据库、GitHub 与 Worker
读取由 control 负责。真实 Access 登录/MFA、GitHub App 全来源回填和目标部署仍待验收。
架构与持久化边界见[控制台功能记录](../../../docs/plan/web-console-kanban.md)。
技术栈为 **React + TypeScript + Vite + Tailwind CSS + shadcn/ui**。
shadcn 的 Button / Input 源码放在 `components/ui/`，按需引入；不使用 CDN、全局状态库或请求缓存库。
前端样式规则统一维护在 [STYLE_GUIDE.md](../../../docs/STYLE_GUIDE.md)，AI 开发入口见 [AGENTS.md](AGENTS.md)。

## 运行与构建

在仓库根目录构建资源后启动 serve（需先准备 PostgreSQL 和 control 配置）：

```sh
python scripts/build_console.py
uv run flowtool serve
```

脚本执行锁定 npm 安装与生产构建，并将 `dist/` 复制到 `app/controler/console_static/`。
随后 `uv build --no-sources` 制作的 wheel/sdist 会包含资源；Docker 使用独立 Node 构建阶段，
运行 serve 不需要 Node。未构建资源时 `/console/` 返回明确的资源不可用错误，不回退到样例。
配置 `FLOWTOOL_ACCESS_ISSUER`、`FLOWTOOL_ACCESS_AUDIENCE` 和 `FLOWTOOL_ACCESS_OWNER_EMAIL`；
Tunnel/Access 将 `/console*` 与 `/api/*` 路由至同一服务并应用相同 owner 策略。
配置缺失会拒绝访问，详见 [Access 部署](../../../docs/deployment/access.md)。

### 前端开发

需要 Node 20.19+（20.x）或 22.12+，建议 Node 24。以下命令在本目录运行：

```sh
npm ci
npm run dev
```

开发服务器默认在 `http://127.0.0.1:5173/console/`，支持 React 快速刷新，
`/api` 代理至本地 serve 的 8000 端口。Vite 不生成 Access JWT，API 仍要求有效的 owner assertion；
单独启动 Vite 无法获得真实数据。开发模式为支持 HMR 移除了页面 CSP，只绑定 loopback；
Vite 页面不受 serve 的生产认证保护，不应公开部署，也不应在前端写入 token 或绕过后端验签。
源码 HTML 不能直接双击运行，也不能直接用普通静态服务器提供，须先经过 Vite。

检查生产构建：

```sh
npm run build
npm run preview -- --port 8767
```

构建结果位于 `dist/`，资源检查地址为 `http://127.0.0.1:8767/console/`；
`vite preview` 沿用本地 `/api` 代理，但不提供生产页面认证或签发 Access JWT，不能替代 serve 的端到端预览。
生产 CSP 允许同源 API，禁止内联脚本。源码目录的 `node_modules/`、`dist/` 和
`test-results/` 不进入 Python 分发包或版本控制；正式静态产物通过构建脚本单独复制打包。

## 页面与读取语义

详情各页签底部的 `ContinueFlowInput` 与「新建 Flow」共用 `FlowTaskInput` 文本组件，保留粘贴换行及输入光标。
继续工作支持 Enter 换行、Ctrl / ⌘ + Enter 发送，中文输入法确认不发送；空白不可提交，最多 16000 字。
切换页签保留草稿，切换 Flow 清空。提交中禁止重复发送；响应不确定时重试沿用 UUID。
`POST /api/flows/{id}/continue` 接收 `message`、`request_id`，要求 owner 同源 JSON。
仅待审核且具有打开 PR、当前 Attempt 和有效 Worker 绑定的 Flow 可继续；未完成任务、结果、停止确认或 triage 会阻止提交。
Service 记录输入并排入普通 `REVISION`，复用已有批次、准备、执行、重试与交付校验；不新建 Flow、分支或 PR，
不伪造 GitHub 评论身份，也不消费待处理反馈或清除待澄清问题。此入口不会主动调用 GitHub 写入 API；
后续 revision 仍遵循现有交付规则。

- `/console/#board`：五列看板、组合查询、服务端分页和各阶段全集计数，PR 优先编号。
- `/console/#flow/<id>/conversation`：GitHub + Agent 时间线、工具摘要、Review 线程、下滑加载和末尾刷新。
- `/console/#flow/<id>/overview`、`/jobs`：概览、来源同步状态、当前动作/下一条件与执行记录。
- `/console/#settings`：Codex / Amp 默认模型与推理强度，顶栏可进入；刷新只读取设置。
- `/console/#flow/<id>/file-<文件ID>`：当前 Flow 内按文件名打开的编辑器页签，可切换和关闭；刷新或离开 Flow 后回到会话重新选择。
- `/console/?q=repo%3Aagentflow+is%3Aactive+pr%3A95#board`：可分享、刷新后恢复的组合查询。

Flow 编号必须来自当前数据库；没有固定可用的样例 ID。GitHub 链接指向真实记录。
API 错误显式显示，已有内容不会被示例数据替换；Worker 离线仍可读已归档内容，未采集历史无法凭空恢复。

详情侧栏顶部的 **Inbox** 汇总当前查询下的「待审核」和「受阻」任务，供人工审核、合并、
排查故障；待处理、进行中和已归档任务不进入 Inbox。条目仅显示任务名称、仓库和 PR/Issue/Flow 编号。
计数使用服务端完整结果，列表复用各阶段的分页；加载失败会提示重试，不显示为空。
点击条目保留当前详情页签，手机点击后关闭任务导航；刷新当前视图同时更新 Inbox。
Inbox 可折叠，原有阶段分组保留；它只提供导航，不自动重试、归档或修改 GitHub。

「设置」按 Codex / Amp 后端分别保存本服务器全局默认值，仅用于新建编码会话。
正在运行或恢复的已有会话不被强制换模型，独立 inference / Judge 不受影响。
模型与推理强度使用预设下拉框，不提供手动输入或实时发现。
模型「不指定」保存为 `null`：Codex 沿用原生模型，Amp 新会话保持 `--mode low` 默认。
Amp CLI `0.0.1794672034-g01d6fa` 支持显式 `--model provider/name`；页面不再提供原生模式选项，
已有会话恢复行为不变。

[`modelPresets.ts`](modelPresets.ts) 保存 2026-11-14 的 CLI 元数据预设快照：
Codex 为本地 CLI 缓存中可见的八个模型；Amp 为已脱敏 `current-models.json` 中
`capabilities.tools=true` 的 53 个模型，保留原始 `id`、`displayName` 及 `capabilities.efforts`。
Codex 强度来自同一缓存的 `supported_reasoning_levels`，并非旧 CLI 的封闭枚举。
这些元数据不代表账号授权或模型执行已验证，没有实时权限或可用性探测。
已保存但不在预设中的模型或强度以「当前值（不在预设中）」保留，读取不会静默清空。
每组只显示模型标题，强度下拉保留可访问名称；顶栏设置入口仅显示图标，不显示静态说明或已读取提示。
未指定强度时，支持 `medium` 的模型在草稿中预选 `mid`，显式保存时提交 `medium`，不再提供「模型默认」选项。
已有显式强度保持不变；预选不会自动写入数据库或修改已有会话。
已知模型只提供自身的强度，Codex 未指定或未知模型可选后端支持的并集。
Amp 未指定模型、未知模型或没有可选强度时，禁用空强度框；已保存的非预设强度仍可保留。
切换模型保留兼容强度，否则预选 `mid`；若支持其他强度但没有 `medium`，需选择可用档位后才能保存。
非空 Amp 强度要求明确模型。服务端负责最终格式和组合校验，不自动保存。

设置通过同源 `GET /api/settings` 读取 `{codex_model, amp_model, codex_effort, amp_effort, revision}`，不使用会话响应缓存。
显式保存以 `PUT /api/settings` 同时提交四项（包括 `null`）和 `expected_revision`；成功响应须回显四项，版本恰好加一。
读取、校验和权限失败保留草稿；409 冲突须先重新读取，再对照服务器当前设置显式保存或选择「使用服务器设置」。
网络、5xx 或不完整的成功响应视为保存结果未知，锁定重发；「回读核对」仅发 GET，并保留草稿供比较，
失败时不解除锁定，也不会自动重发 PUT。离开设置时取消读取；迟到响应不能覆盖新页面或读取期间编辑的草稿。
草稿与未知结果保护在当前页面内存中保留，切换设置、看板和详情不会丢失；整页刷新或关闭前应先回读核对。
返回看板保留查询、未提交的搜索输入、阶段、滚动与分页状态；原有 Flow 深链接和会话缓存保持独立。

「新建 Flow」选择 Project（代码仓库）并填写任务内容，不必关联 Issue。项目来自授权 installation 的分页仓库清单，
不依赖历史 Flow；可继续读取空的中间页、重试或重新读取，并保留草稿。
前端只提交 `task_content` 字符串，不推导或提交标题；全文保留前导空白和粘贴的 CRLF 等换行，
最多 32 KiB UTF-8；空白/NUL/超限输入拒绝。创建后由服务器异步生成标题，刷新后显示；
显示优先级为生成标题 → 缓存的 Issue 标题 → PR 标题 → `Flow #ID`。
服务端返回的 `title` 已合并前三项；为 null 时前端直接回退 `Flow #ID`，不使用 Issue/PR 编号代替标题。
身份徽标与链接仍独立保留 PR/Issue 编号，不受标题是否生成影响。
提交中禁用重复操作与关闭，成功后直接打开新 Flow 概览，不受看板筛选影响。
明确拒绝保留可编辑草稿；网络、5xx 或不完整成功响应提示结果未知并锁定重发，提供清空筛选、刷新核对入口。
草稿只保存在本页内存，刷新页面会丢失；不要在核对前重复创建。
无 Issue Flow 的概览使用现有安全 Markdown 渲染完整任务字符串，不生成 Issue 链接。

顶栏只有一个查询框，支持普通关键词、双引号短语、`repo:`、`is:active|archived`、
`status:queued|running|review|blocked|archived`、`issue:`、`pr:`；词和条件之间为 AND。
五列依次为待处理、进行中、待审核、受阻、已归档。Flow 生命周期为
`queued/running/review/blocked/finalizing/archived`，其中 `finalizing` 映射到 `running` 列，
卡片及主徽标以 `phase` 为准，详情可查看真实生命周期与当前动作。
`is:archived` 与 `status:archived` 查询真实业务归档；`is:active` 排除已归档 Flow，包含受阻与收尾中的 Flow。
PR 合并、关闭或停止执行都不等于业务归档，只有生命周期为 `archived` 才进入已归档列，
结果标记为成功或废弃。`is:done` 和 `status:done` 均无兼容别名，提交会提示无效查询。
Enter 提交；聚焦或输入字段显示统一建议，方向键 / 点击选择，Enter 补入后再次 Enter 提交。
中文组合输入不提交；Escape 关闭建议，清空恢复全部结果，浏览器前进/后退恢复已提交查询。
无效、重复或未知条件提示错误，保留上一有效结果；不实现 GitHub 全套搜索语法。

未归档且不在收尾中的 Flow 可在「概览 → 当前动作」点击「结束本轮」，在内联表单选择
成功（`succeeded`）或废弃（`abandoned`），并填写非空结论。UI 统一要求结论，
包括无 PR 的成功结束；不会使用浏览器确认框或输入框。
`POST /api/flows/{id}/archive` 提交同源 JSON
`{reason, summary, expected_round_no}`，轮次取自当前详情。
表单打开后若刷新发现轮次变化，必须关闭并重新核对，不能把旧表单提交到新轮次。
受理只表示发起结束本轮，不承诺立即归档；停止确认、结果对账及收尾未完成前不会归档。
收尾中仍显示「进行中」，详情注明 `finalizing`，不提供重复结束或重试入口。
`archive_reason`、`archive_summary` 展示本轮结束目标/归档结果和结论；
`archived_at` 是真实业务归档时间，不再存在 cancelled-only 展示归档。

已归档 Flow 只提供显式「恢复推进」，通过 `POST /api/flows/{id}/resume`
提交 `{expected_round_no}`。页面明确提示：同一 Flow 开启新轮次、从待处理开始，后续使用新 PR，
保留历史；不复用 `/retry` 恢复归档轮次，也不提前移动卡片。

只有 `blocked` Flow 可在「概览 → 当前动作」点击「重试」。
`POST /api/flows/{id}/retry` 同样只接受 owner 的同源空 JSON，复用 `ControlService.retry`；
仍需满足停止确认、结果对账、PR 状态、活跃 Flow 冲突及原 Worker 归档绑定等检查。
没有可重试工作或安全检查未通过时返回 409，并在页面解释原因；不存在返回 404。
提交期间三个操作互斥，受理后按返回详情刷新分组，不提前移动卡片，也不承诺任务已运行。
结束/恢复的 409 会显示未受理及后端错误码，保留当前详情和表单，不显示成功通知。
网络异常可能发生在提交之后，页面会提示先刷新核对，不自动重发；切换 Flow 不受旧响应覆盖。
清理受阻仍属于「受阻」，不会因 PR 合并显示为已归档。Job 的 `done` 状态与 Flow 阶段独立，保持不变。

本次阅读固定本地已提交快照，编辑和补录在末尾显式刷新后才进入新快照；线程回复使用同一快照。
下滑阅读在距已加载内容末尾约两屏时预取下一页，预取距离随阅读区高度变化，追加内容保留当前阅读位置。
刷新活跃 Flow 会排队后台同步，响应不等待 GitHub/Worker 全部抓取；来源可能仍是
pending/syncing/partial/unavailable，“没有新增”只描述当前已归档快照。
已观察版本和删除标记永久保存，首次采集前的历史编辑/删除及远端已过期内容无法还原。
来源明细保留 GitHub 提交列表 250 条上限、线程缺少远端变更时间等固定限制；这些限制
不会因重试消失，不单独触发同步告警。真实的同步异常仍提示并提供重试。
GitHub Projects 的状态同步保持原语义，只有 Flow 成功完成清理后才标记 Done。
启动时更新阶段或动作规则已变化的既有投影，不需要等待下一次 GitHub 事件；重复启动不重复发布。
“已编辑”按需展示相对前一正文版本的 diff；元信息变化和删除不误报正文编辑。
完整 patch 由后端限定预算后一次返回，前端每窗口最多挂载 200 行，保持文本安全。
GitHub 末尾 effect 标记在展示读取时移除，原始归档不变；预览、全文分段和 diff 使用同一
展示正文。无正文事件显示紧凑动作摘要，标签名称直接可见。连续同来源、同作者的消息共用
头像、作者栏与来源定位，包含 developer/system/user；Worker 还必须有相同的执行、会话与
会话代次归属，已有 assistant/tool 输出分组保持不变。连续同作者的检查与无正文事件可跨来源
汇总为默认收起的「操作记录」，展开后保留每条动作、状态、时间、正文与来源信息；单条操作
保持直接可见。普通消息或不同作者会截断操作分组，评审线程、删除记录与不同历史归属
不合并；每条正文、来源链接及编辑记录独立保留。连续工具调用和结果汇总为默认收起的
工具活动，展开后按调用顺序查看，同 call_id 的结果归到对应调用下。用户消息、其他来源或
不同执行归属会截断工具分组；缺少归属信息的 Worker 记录不自动合并。分组、统计、来源数量与结果归属
均依据已读快照的轻量身份，不受窗口移动或正文缓存淘汰影响；重复 call_id 匹配最近的前置调用，
空 ID 或无对应调用的结果可独立阅读，不为配对加载全部正文。
工具／操作组仅点击时展开，整组离开详情可视区后自动收起；仅标题离屏、正文仍可见时保持
展开。刷新导致组成员增删时，只要当前可见成员仍在就保持展开。重进页签默认折叠，按逻辑阅读行
与偏移恢复；已折叠的成员对应到本组摘要，普通消息不沿用展开布局的旧滚动值。
正文和工具中的文件预览滚动到末尾自动接续读取，已显示内容保持在上方，不再左右翻段；
失败保留已有内容并可重试原请求。长正文片段复用虚拟列表，卸载时释放当前组件中的文本，
回滚时复用缓存或按原版本重读。
消息与线程回复在当前有界正文段内渲染 Markdown/GFM，支持标题、列表、链接、引用、代码与
表格；跨段语法按各段独立解析，不额外读取整篇正文。工具输出和 diff 保持原文。原始 HTML
仅显示转义文本，危险 URL 被过滤；图片显示为链接，不自动请求外部资源。
消息、工具活动、代码块与宽表格的排版规则见 [样式指南](../../../docs/STYLE_GUIDE.md#布局窄屏与长内容)。
普通相对链接（含片段）与图片地址按消息原始来源 URL 解析；来源缺失或无效时保留文字，
不将相对目标跳到控制台域名。GFM 脚注使用每条正文独立的引用、标题及回链 ID；点击或键盘
激活时仅在当前正文段内定位并转移焦点，不覆盖会话 hash 路由，也不打开新窗口。
脚注标签先映射为内部数字标识，避免 `a` 的重复引用与 `a-2` 标签生成相同引用 ID；
显示编号、脚注正文及每次引用的回链不变。仅脚注定义添加程序化焦点入口，回链保留原引用的
Tab / Shift+Tab 顺序。

Worker 正文已由 worker 在返回历史前把成功登记的本地 Markdown 目的地址替换为 controller URL；
前端不接收路径映射，也不能提交本地路径申请读取。仅 Worker 活动中精确匹配同源
`/api/files/<32位小写十六进制ID>` 的链接与图片入口，在普通相对地址解析之前识别。
新链接附加 `#name=<百分号编码的 basename>`，只供页签和下载命名；不包含本地目录，
HTTP/RPC 仍只接收随机 ID。文件名片段须通过长度、解码与路径/控制字符校验；旧链接回退到链接文字或短 ID。
点击或 Enter 在当前 Flow 打开文件名页签，焦点随之转移；同 ID 只打开一次，多文件独立切换，
同名文件附短 ID 区分。页签带关闭按钮，聚焦页签按 Delete 也可关闭；关闭当前文件选择相邻文件，
最后一个关闭后回到会话。长文件名省略并通过悬停显示全名；窄屏仅标签栏横向滚动，当前文件与关闭按钮一起滚入视野。
不弹出浏览器窗口，切回会话沿用逻辑阅读位置恢复。图片在会话中仍只是链接，不自动读取。
普通外链、跨域同路径、GitHub 相对链接、缺少来源的普通相对地址与脚注不改变原行为。

文件读取复用 owner 鉴权的 attachment API，不改变下载响应；请求无缓存、可取消，
切换页签或 Flow 后旧响应不能覆盖当前文件。按实际响应流限制最多 512 KiB，空文件可查看；
在此上限内完整读取后预览，仅挂载当前文件；切回文件会重新读取，不缓存文件内容，也不使用下文的会话响应缓存。
超限时预览与同一 API 下载均不可用，不提示绕过限额。UTF-8 文本、Markdown、HTML 和 SVG
统一按带行号的等宽转义源码分段显示（每段最多 8192 字符、200 行），不执行脚本或加载文内资源。
行号对应原文件，保留空行和缩进；软换行不增加行号，长单行跨段继续使用同一行号。
按行数翻段时从下一源文件行开始，LF／CRLF 与 Unicode 代理对不在段间拆开。
行号不进入源码、复制内容或屏幕阅读器文本；会话正文和工具代码不增加行号。
PNG/JPEG/GIF/WebP 必须通过内容签名和浏览器解码验证，才以已有 CSP 允许的 data 图片显示；
伪装图片、非 UTF-8 与其他二进制仅提供原下载入口，无需放宽 CSP 或添加 Blob 执行权限。
页面区分登录失效／无权限、文件缺失／替换、超限、离线、繁忙、超时和不可读，并提供重试或重新登录入口。
已开文件只保存在当前 Flow 详情内存，刷新、离开 Flow 或后退至已关闭文件时回到会话；
没有独立 `#file` 页面或全局文件列表。预览区使用紧凑只读工具栏，不重复文件名标题或展示句柄。
文件是原 Worker 当前内容，不是快照，不承诺离线可读。

个人阅读状态未落库，另见 [#88](https://github.com/b1indsight/agentflow/issues/88)。

## 渲染与阅读约定

手机详情滚动阅读后自动收起头部，可手动展开，回到顶部自动展开；切换高度时补偿正文阅读位置。
收起后隐藏的导航不再接收焦点；桌面保持展开。

- 手机未显示的看板阶段列仍保留测量，避免虚拟列表复显错位。
  从设置或详情返回时，各列复用窗口层按可见卡片及偏移恢复阅读位置，避免重挂载后估计高度变化导致移位；
  详情返回仍恢复卡片焦点，手机切换阶段保留阅读位置。
- 看板各列使用独立滚动根，侧栏分组、执行记录、关键进展、会话、正文块、Review 回复使用各自页面的共享滚动根。
  会话显示行由数据定义，组摘要与展开后的各条正文独立虚拟化；调用和结果各占稳定的一行，
  每行最多一条正文。每个列表最多挂载 60 个行容器，摘要、正文、上下各 3 行预渲染及
  焦点／恢复目标共享该硬预算，极高视口也不例外。挂载行以普通文档流衔接，仅未挂载区间使用估计高度占位。
  会话以首个完整可见行及像素偏移为锚，无完整行时用相交行；窗口层统一补偿上方变化，
  行自身及下方增高正常向后排布。
  直接大跨度跳到未挂载区间时，窗口更新前仍可能短暂留白；不承诺所有跳转都无空白帧。
- 正文每段最多 2048 字符，代码每段最多 8192 字符且不超过 200 行；正文向下滚动自动续读，
  每次请求最多 2048 / 8192 个 Unicode 码点，每个正文列表最多挂载 60 页，保留全部内容可达性。
  标题与元信息仍使用有界预览和分段控件，不把长单行静默截断。
- 仓库建议每组最多 8 条，可翻组。正文分段、来源面板和差异阅读状态独立于 DOM 保存，
  卸载或组收起后仍保留；临时展开状态按上述可视区规则重置。完整来源信息按需分页读取，只保留一页、最多 20 条记录。
- 会话缓存最多 4 个 Flow，合计估算容量不超过 16 MiB，每个 Flow 最多保留 240 条活动正文；历史逻辑长度不因正文淘汰缩短，
  保留轻量身份及不透明页游标，在同一快照内回读。切换快照重建分页，跟随请求期间最新的
  逻辑阅读目标，不混合新旧快照或恢复请求开始时的旧滚动位置。新页仅延长折叠组、未增加显示行时
  仍按分页游标自动续读，直到末尾离开预取范围、快照读完或请求失败，无需手动点击。
  缓存的分页错误返回后可重试。整个 Flow 的身份缓存淘汰后，若重载首页找不到旧阅读行，
  回到当前已读内容，不为恢复位置自动扫描未读历史。空快照同样缓存，返回已读 Flow 会更新其最近使用顺序。
- 正文分段和编辑 diff 共缓存最多 64 个成功响应、估算容量不超过 4 MiB；线程回复缓存最多 12 页、2 MiB（每页最多 20 条）。
  正文按 Flow、记录、版本、偏移及长度区分，diff 与正文分开；回复按 Flow、线程、快照及游标区分。
  切换页签或虚拟行重新挂载后复用已读数据，条目数或容量超限均淘汰最久未使用项，之后按需重读；
  单条数据超过所属缓存的容量上限时仍正常返回、显示，但不留在缓存中，也不挤掉其他条目。
  同键更新超限会移除该键的旧缓存，避免重新打开时显示旧快照；再次访问超大会话需要重新读取。
  失败和取消不写入响应缓存，也不共享仍在执行的请求，避免旧页面取消新页面的读取。
  显式刷新仍请求服务端，新版本/快照不会命中旧内容；看板、详情、执行状态和写操作不使用此缓存。
  缓存仅保留在当前页面内存，整页刷新或关闭后清空，不使用 localStorage、sessionStorage 或 HTTP 缓存。
- 虚拟列表关闭 React 适配器的强制同步更新，避免尺寸测量期间立即提交布局而触发
  ResizeObserver 循环告警；保留原有测量、窗口上限与阅读恢复，不屏蔽浏览器错误。

三类缓存的估算载荷预算合计 22 MiB，按键和值的 JSON 长度 × 2（UTF-16 字节）记账；
会话的活动 Map 转为条目后计算，正文、元数据、身份和页游标都计入，不只统计文本长度。
该值不等于 JavaScript 堆占用：对象/Map 开销、估算时的临时字符串、当前 React 渲染状态、
虚拟测量和阅读状态不在此预算内。超大会话可继续阅读，但不跨页签保留；不宣称整个应用总内存固定。


```sh
CI=1 PLAYWRIGHT_PORT=5175 npm run test:e2e -- --workers=2 --grep 'direct Flow|creation'
```

```sh
CI=1 PLAYWRIGHT_PORT=5175 npm run test:e2e -- e2e/settings.spec.ts --workers=2
```
